# SPO: Single-stream Policy Optimization — Reproduction

A faithful, CPU-only reimplementation of **Single-stream Policy Optimization**
(Xu & Ding, *NeurIPS 2025 MATH-AI Workshop*), generalized from the LLM-RLVR
setting of the paper to a **contextual-bandit / tabular RL** setting.

The paper trains an 8B LLM with a verifiable-reward RL loop, which requires a
large multi-GPU stack (verl + ReTool, Qwen3-8B, a Python-tool environment). The
**SPO algorithm itself is independent of all that**. As the paper notes, the
core idea is "the value of a prompt `x` under policy `π`" — which generalizes
directly to "the value of a state `s` under policy `π`". This repo implements
SPO at that general level so the entire paper can be reproduced on a laptop in
under a minute.

## The mapping (LLM → general RL)

| Paper (LLM-RLVR) | This repo (tabular) |
|---|---|
| prompt `x` | discrete state / context `s` |
| response `y` | action `a` |
| binary verifiable reward `r ∈ {0,1}` | Bernoulli bandit reward `r ∈ {0,1}` |
| `v̂(x) ≈ V_π(x)` | `v̂(s) ≈ V_π(s)` (per-state success prob) |
| KL between policies on prompt `x` | per-state softmax KL |
| per-token PPO-Clip | per-step PPO-Clip |

Because rewards stay **binary**, the Beta value tracker, the Bernoulli-variance
prioritized sampler, and the degeneracy analysis all transfer **exactly**.

## What's implemented

Core algorithm (`spo/`):
- **`tracker.py`** — the KL-Adaptive Bayesian value tracker (Eqs. 1–3). Beta
  parameterization with KL-driven forgetting `ρ = 2^(−D/D_half)`; provably
  equivalent EMA form for general rewards; offline init (Eq. 2). **O(1) memory
  per state — no reward buffer.**
- **`advantage.py`** — prioritized sampling (Eq. 7), pre-update-baseline raw
  advantage (Eq. 4), global batch normalization (Eq. 5).
- **`policy.py`** — tabular softmax policy with PPO-Clip (Eq. 6) and the
  Clip-Higher trick (`ε_low=0.2, ε_high=0.28`); per-state KL.
- **`spo_trainer.py`** — Algorithm 1 + Algorithm 2 (offline init).
- **`grpo_trainer.py`** — GRPO baseline (group mean baseline, per-group
  normalization, degenerate-group handling) for head-to-head comparison.

Experiments (`experiments/`), each writes a figure to `figures/`:
1. **`run_comparison.py`** — SPO vs GRPO under matched compute (analog of
   Table 1 + the Figure 3a signal-efficiency plot).
2. **`run_ablations.py`** — baseline / offline-init / batch-norm / prioritized
   sampling ablations (analog of Figure 2).
3. **`run_variance.py`** — variance decomposition of Eq. 12 (Appendix E.2),
   analytic + Monte-Carlo.
4. **`run_throughput.py`** — agentic throughput / bottleneck simulation,
   reproducing the ~4.35× group-free speedup (Appendix I, Figures 4 & 5).

Documentation (`docs/`):
- **`SPO_explained.pdf`** — a plain-language, diagram-heavy explainer of the
  whole method and the results (no math background assumed).
- **`make_diagrams.py`** — regenerates the schematic diagrams in `docs/diagrams/`.
- **`build_pdf.py`** — rebuilds the PDF from the diagrams and the result figures
  in `figures/`. Run `python experiments/run_*.py` first to (re)generate the
  result figures, then `python docs/make_diagrams.py && python docs/build_pdf.py`.

## Results reproduced

Running on CPU (5 seeds, ~30s total):

| Claim | Paper | This repo |
|---|---|---|
| SPO > GRPO (final performance) | +3.4 pp maj@32 | **+5.3 pp** mean value, all seeds |
| GRPO degenerate-group waste | 60–80% | 20–40% (depends on difficulty mix) |
| Batch-norm is the most critical ablation | yes (Fig 2d) | yes (largest drop) |
| Variance ratio worst at easy/hard prompts | ~1.97 @ p=0.1/0.9 | **1.89** (Eq. 12) |
| Group-free throughput speedup | 4.35× | **4.0–4.6×** |

(Exact numbers differ because several hyperparameters — `D_half`, `ψ_G`, the
agentic latency distribution — are not fully specified in the paper. The
*qualitative* claims all hold.)

## Going back to LLMs

The algorithm code is environment-agnostic. To use real LLM-RLVR, you replace
`ContextualBandit` with a prompt dataset + a generation backend, and
`TabularPolicy` with your model + PPO-Clip on token log-probs. The tracker,
advantage pipeline, and prioritized sampler are unchanged: `tracker.update(...)`
keyed on a prompt ID instead of a state ID. That is the surgical diff from a
standard GRPO loop:
1. swap `group_mean()` baseline → `tracker.v_hat(prompt_id)`,
2. swap per-group normalization → batch normalization,
3. add the tracker update + prioritized sampler.

## Notes / faithfulness caveats

- The PPO-Clip update is a single-sample tabular gradient ascent on the clipped
  surrogate; it matches the paper's loss form but is much smaller-scale.
- The KL `D(s)` that drives forgetting is computed from the stored logits of the
  last-acting policy at each state — the tabular analog of caching the last
  response's token log-probs per prompt.
- Difficulty spread across states is what makes degeneracy and the curriculum
  meaningful; with uniform difficulty those effects shrink (as in the paper's
  low-variance agentic regime).
